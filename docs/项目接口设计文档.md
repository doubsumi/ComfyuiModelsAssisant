# 项目接口设计文档

## 0. 全局约定

### 0.1 类型约定

| 类型             | 含义                     |
| -------------- | ---------------------- |
| `ModelEntry`   | 模型注册表条目，见 §1.2         |
| `Architecture` | 架构定义，见 §1.3            |
| `GraphPattern` | 图谱模式，见 §1.4            |
| `Preset`       | 预设，见 §1.5              |
| `Patch`        | LLM 生成的更新包，见 §1.6      |
| `WorkflowJSON` | ComfyUI 工作流 JSON，UI 格式 |

### 0.2 错误处理约定

所有服务层方法采用**返回结果对象**而非抛异常的模式：

```
Result<T> = {
  ok: boolean
  data?: T
  error?: {
    code: string            # 机器可读错误码
    message: string         # 人类可读信息
    details?: any           # 结构化上下文
  }
  warnings?: Warning[]      # 非致命问题
}
```

路由层负责把 `Result` 转换为 HTTP 状态码 + JSON body。

| 编号   | 模块                  | 层  | 依赖     |

## 1. 数据结构定义

### 1.1 ModelEntry

```
ModelEntry = {
  # 基础
  file: string                    # 文件名（含扩展名）
  dir: string                     # 一级子目录名
  sizeBytes: int
  mtime: ISO8601
  
  # 识别结果
  arch: string | null             # 架构 ID
  role: Role                      # 见下方枚举
  source: Source                  # metadata | heuristic | llm_patch | initial
  confidence: float               # 0.0 ~ 1.0
  needsLlm: boolean               # 是否需要 LLM 补全
  signals: string[]               # 推断依据
  missingFields: string[]         # 缺失的关键字段

  # Layer 1a 提取
  metadata: {
    rawKeys: string[]
    baseModelVersion?: string
    networkModule?: string
    loraRank?: int
    loraAlpha?: float
    modelspecArch?: string
    title?: string
    triggerWord?: string
    tensorCount?: int
  }

  # 架构相关（LLM 补全后填充）
  compatibleEncoders?: string[]
  compatibleVaes?: string[]
  compatibleLoras?: string[]      # 架构 ID 列表
  encoderNodeParams?: object      # { type: "krea2" }

  # LoRA 相关
  triggerWord?: string
  defaultWeight?: float

  # 参数
  defaultParams?: {
    steps?: int
    cfg?: float
    sampler?: string
    scheduler?: string
    denoise?: float
  }
}

Role = "unet" | "encoder" | "vae" | "videoVae" | "audioVae" | "lora" | "checkpoint" | "unknown"
Source = "metadata" | "heuristic" | "llm_patch" | "initial"
```

### 1.2 Architecture

```
Architecture = {
  id: string                      # 例如 "krea2"
  label: string                   # 显示名
  unetFolder: string              # "diffusion_models" / "unet" / "checkpoints"
  encoders: string[]              # 兼容的 encoder 文件名
  encoderNode: string             # "CLIPLoader" / "DualCLIPLoader"
  encoderNodeParams: object       # 该节点需要的固定参数
  vae: string | string[]          # 单个或多个 VAE
  defaultParams: object
  loraCompatibility: string       # 兼容的 LoRA 架构标签
}
```

### 1.3 GraphPattern

```
GraphPattern = {
  id: string                      # 与 arch id 对应
  version: string                 # 图谱模式版本，与 registry 独立
  nodes: NodeSpec[]
  connections: ConnectionSpec[]
  loraInsertion: LoraInsertionSpec | null
  optionalNodes: OptionalNodeSpec[]
  modelInjections: ModelInjectionSpec[]
  paramInjections: ParamInjectionSpec[]
  promptInjections: PromptInjectionSpec[]
  pluginDependencies: string[]    # 需要安装的插件名
}

NodeSpec = {
  key: string                     # 内部引用键（如 "unet", "sampler"）
  type: string                    # ComfyUI 节点类型
  pos: [int, int]
  size: [int, int]
  widgets: string[]               # widget 名称（按顺序）
  widgetsDefaults: any[]          # 与 widgets 一一对应
  flags?: object
}

ConnectionSpec = {
  from: string                    # 源节点 key
  fromSlot: int
  to: string                      # 目标节点 key
  toSlot: int
  type: string                    # "MODEL" / "CLIP" / "LATENT" / ...
}

LoraInsertionSpec = {
  from: string                    # 上游节点 key（通常 "unet"）
  to: string                      # 下游节点 key（通常 "sampler" / "guider"）
  targetSlot: int                 # 目标节点的输入槽位
  nodePos: [int, int]
  nodeSize: [int, int]
}

OptionalNodeSpec = {
  key: string                     # "firstFrame" / "lastFrame" / "refImage"
  type: string                    # "LoadImage" / "VHS_LoadVideo" / "LoadAudio"
  targetKey: string               # 接收该输入的节点 key
  targetSlot: int
  pos: [int, int]
  size: [int, int]
  widgets: string[]
  widgetsDefaults: any[]
}

ModelInjectionSpec = {
  nodeKey: string                 # 目标节点 key
  widgetIndex: int                # widgets_values 中的下标
  modelRole: string               # "unet" / "encoder" / "vae" / "videoVae" / ...
}

ParamInjectionSpec = {
  nodeKey: string
  widgetIndex: int
  paramName: string               # 用户参数名
}

PromptInjectionSpec = {
  nodeKey: string
  widgetIndex: int
  role: "positive" | "negative" | "videoPrompt"
}
```

## 2. 模块接口

### 2.1 M1 · FileManager

**职责**：提供模型文件的原始清单与用户备注。

```
class FileManager:

  # ---- 扫描 ----
  
  scan(modelsDir: string) -> Result<ScannedFile[]>
    """递归扫描目录，返回支持的文件列表。
       过滤：扩展名、跳过目录、一级子目录结构。
       不做任何架构推断。"""
    # ScannedFile = { file, dir, sizeBytes, mtime, absPath }

  getCachedScan(modelsDir: string, maxAge: int = 300) -> ScannedFile[] | null
    """读取缓存，若超过 maxAge 秒则返回 null。"""

  # ---- 备注 ----
  
  getNote(file: string, dir: string) -> string | null
    """读取用户对该文件的备注。"""

  setNote(file: string, dir: string, note: string) -> Result<void>
    """写入备注。空字符串表示删除。"""

  getAllNotes() -> Map<string, string>
    """返回所有备注。key = "dir/file"。"""
    # 用途：前端一次性加载，避免每条记录单独请求

  clearAllNotes() -> Result<void>
```

### 2.2 M2 · ModelRegistry

**职责**：模型元数据的中央存储与查询。

```
class ModelRegistry:

  def __init__(self, store: RegistryStore, scanner: ModelScanner):
    ...

  # ---- 加载 ----
  
  load() -> Registry
    """加载完整注册表（含架构定义）。首次调用时缓存到内存。"""

  reload() -> Registry
    """强制从磁盘重新加载（Patch 合并后调用）。"""

  # ---- 查询 ----
  
  getModel(file: string, dir: string) -> ModelEntry | null

  getModelsByRole(role: Role) -> ModelEntry[]

  getModelsByArch(arch: string) -> ModelEntry[]

  getArchitecture(archId: string) -> Architecture | null

  listArchitectures() -> Architecture[]

  # ---- 差异查询 ----
  
  getUnregistered(scanned: ScannedFile[]) -> ModelEntry[]
    """返回扫描结果中不在注册表的条目。
       使用 Layer 1a + 1b 生成初步 ModelEntry。"""

  getIncomplete(scanned: ScannedFile[]) -> ModelEntry[]
    """返回注册表中已存在但 needsLlm=true 的条目。"""

  # ---- 更新 ----
  
  mergePatch(patch: Patch) -> Result<MergeStats>
    """字段级合并 Patch 到注册表。
       合并规则见 §3.2。
       合并后自动保存并记录历史。"""
    # MergeStats = { added, updated, total }

  rollbackToPatch(patchId: string) -> Result<void>
    """回滚到指定 Patch 应用前的状态。
       实现：从 patchHistory 反向应用差异。"""
    # 注意：回滚不删除注册表条目，只恢复被 Patch 覆盖的字段

  # ---- 导出 ----
  
  exportSnapshot() -> Registry
    """返回当前注册表快照（用于备份）。"""
```

### 2.3 M2.1 · ModelScanner

**职责**：Layer 1a + 1b 的纯函数实现，无状态。

```
class ModelScanner:

  # ---- Layer 1a ----
  
  readSafetensorsHeader(absPath: string) -> Result<SafetensorsHeader>
    """读取 safetensors 头部（不加载 tensor）。
       异常情况返回 Result.error。"""
    # SafetensorsHeader = { metadata: object, tensorNames: string[] }

  extractMetadata(header: SafetensorsHeader) -> ExtractedMetadata
    """从 header.metadata 中提取已知字段。
       返回结构见 §1.1 的 metadata 字段。"""

  # ---- Layer 1b ----
  
  inferArchitecture(tensorNames: string[], fileName: string) -> InferenceResult
    """推断架构和角色。
       优先匹配文件名，其次匹配 tensor 名称特征。
       返回 { arch, role, confidence, signals }。"""
    # InferenceResult = { arch: string | null, role: Role, confidence: float, signals: string[] }

  # ---- 组合 ----
  
  scanSingle(absPath: string, modelsDir: string) -> ModelEntry
    """对单个文件执行完整的 Layer 1a + 1b。
       返回的 ModelEntry 中 source 为 metadata 或 heuristic。
       needsLlm 根据 confidence 判定。"""

  scanDirectory(modelsDir: string) -> ModelEntry[]
    """批量扫描。内部按顺序调用 scanSingle。"""
```

### 2.7 M3 · CompatibilityEngine

**职责**：判断一组模型是否可组合，给出诊断和建议。

```
class CompatibilityEngine:

  def __init__(self, registry: ModelRegistry):
    ...

  # ---- 主入口 ----

  # ---- 辅助 ----

**请求结构**：

```
CompatibilityRequest = {

CompatibilityResult = {

Missing = {
  role: string
  reason: string

### 2.9 M4.1 · GraphBuilder

**职责**：从 GraphPattern 实例化具体的节点图。

```
class GraphBuilder:

  def __init__(self, registry: ModelRegistry, patternStore: GraphPatternStore):
    ...

  # ---- 主流程 ----
  
  build(pattern: GraphPattern, request: GenerateRequest) -> BuildResult
    """实例化流程：
       1. 复制 pattern.nodes 为工作节点列表
       2. 按 modelInjections 注入模型文件名
       3. 按 paramInjections 注入参数
       4. 按 promptInjections 注入提示词
       5. 按 loraInsertion 动态插入 LoRA 链
       6. 处理 optionalNodes（按 request.optionalInputs 激活或移除）
       7. 构建 connections 与 links"""

  # ---- 子步骤（供单元测试）---
  
  _instantiateNodes(pattern: GraphPattern) -> WorkingNode[]
    """将 NodeSpec[] 转换为 WorkingNode[]，分配节点 ID。"""

  _injectModels(nodes: WorkingNode[], pattern: GraphPattern, request: GenerateRequest) -> void
    """按 modelInjections 修改 widgets_values。"""

  _injectParams(nodes: WorkingNode[], pattern: GraphPattern, request: GenerateRequest) -> void

  _injectPrompts(nodes: WorkingNode[], pattern: GraphPattern, request: GenerateRequest) -> void

  _insertLoras(nodes: WorkingNode[], pattern: GraphPattern, request: GenerateRequest) -> void
    """插入 LoRA 链：
       - 无 LoRA：短路 unet → sampler
       - N 个 LoRA：链式插入节点，分配 ID（从 pattern 预留区间取）"""

  _applyOptionalNodes(nodes: WorkingNode[], pattern: GraphPattern, request: GenerateRequest) -> void
    """激活或移除 optionalNodes。"""

  _buildLinks(nodes: WorkingNode[], pattern: GraphPattern) -> Link[]
    """根据 connections + 动态插入的关系构建 links 数组。"""
```

**节点 ID 分配策略**：

- 基础节点使用 pattern 中预分配的 ID（如 1-100）
- LoRA 节点使用预留区间（如 1000-1099，按需扩展）
- Optional 节点使用另一预留区间（如 2000-2099）
- 分配后更新 `last_node_id`

**links 数组构建规则**：

- link\_id 从 1 开始递增
- 每条 link 格式：`[link_id, source_node_id, source_slot, target_node_id, target_slot, type]`
- 仅保留双向 link 关系，`inputs[].link` 和 `outputs[].links` 必须一致

### 2.10 M4.2 · WorkflowSerializer

## 3. 关键算法

### 3.1 Layer 1b 启发式推断

```
输入：tensorNames: string[]（截取前 5000 个），fileName: string
输出：{ arch, role, confidence, signals }

流程：
1. 文件名优先匹配
   for (pattern, arch, role) in NAME_PATTERNS:
     if fileName matches pattern:
       return { arch, role, confidence: 0.95, signals: [pattern] }

2. tensor 名称打分
   scores = {}
   for (arch, signature) in ARCH_SIGNATURES:
     score = 0
     for (regex, weight) in signature.positive:
       matchCount = count of tensorNames matching regex
       if matchCount > 0:
         score += weight * min(matchCount, 5) / 5
     for (regex, weight) in signature.negative:
       if any tensorNames match regex:
         score += weight
     scores[arch] = score

3. 置信度计算
   top = max(scores)
   second = second_max(scores)
   gap = top - second
   confidence = min(1.0, (top / 100) * (gap / max(top, 1) + 0.5))

4. 特殊情况
   if top arch == "sd15_sdxl":
     check conditioner.embedders.1 → sdxl / sd15

5. needsLlm 判定
   needsLlm = (confidence < 0.6) or (arch is null)
```

### 3.2 Patch 合并规则

```
输入：registry, normalizedPatch
输出：MergeStats

对 patch.models 中的每个 entry：
  key = (entry.file, entry.dir)
  old = registry.models[key]

  if old 不存在:
    registry.models[key] = { ...entry, source: "llm_patch" }
    added++

  elif old.source in ("heuristic", "unknown"):
    # 覆盖式合并
    for field in OVERWRITABLE_FIELDS:
      if field in entry and entry[field] != old[field]:
        old[field] = entry[field]
    old.source = "llm_patch"
    old.needsLlm = false
    old.confidence = 1.0
    updated++

  elif old.source in ("metadata", "initial", "llm_patch"):
    # 填充式合并
    for field in FILLABLE_FIELDS:
      if field in entry and not old.get(field):
        old[field] = entry[field]
        updated++

OVERWRITABLE_FIELDS = [arch, role, compatibleEncoders, compatibleVaes,
                        compatibleLoras, defaultParams, encoderNodeParams,
                        triggerWord, defaultWeight]
FILLABLE_FIELDS = [triggerWord, defaultWeight, encoderNodeParams,
                   compatibleEncoders, compatibleVaes, compatibleLoras]
```

### 3.3 Patch 校验规则

按顺序执行，任一步骤返回 error 立即终止：

```
Step 1: 顶层结构
  - patch 是对象
  - patchVersion 存在且 == registry.version
  - patch.models 是数组

Step 2: 建立扫描索引
  - scannedKeys = Set of (file, dir) from scan cache

Step 3: 逐条校验（对每个 model）
  3.1 基础字段
      - file 存在且非空
      - dir 存在且非空
      - (file, dir) 在 scannedKeys 中
  3.2 arch
      - 允许 null
      - 非 null 时必须是 registry.architectures 的 key
  3.3 role
      - 必须在 VALID_ROLES 中
  3.4 条件字段
      - role=unet → compatibleEncoders 和 compatibleVaes 建议非空（warning）
      - role=encoder → encoderNodeParams 建议存在（warning）
      - role=lora → defaultWeight 若存在则必须在 [0, 2]（warning + 自动裁剪）

Step 4: 判定
  - 存在 error → valid = false
  - 全部通过 → valid = true，返回 normalizedPatch
```

### 3.4 LoRA 链插入算法

```
输入：nodes（已实例化的基础节点）, pattern, request.loras
输出：修改后的 nodes（含 LoRA 节点）

1. 定位插入点
   fromKey = pattern.loraInsertion.from      # 通常 "unet"
   toKey = pattern.loraInsertion.to          # 通常 "sampler" 或 "guider"
   targetSlot = pattern.loraInsertion.targetSlot

2. 若无 LoRA
   直接连接 fromKey.output[0] → toKey.input[targetSlot]
   return

3. 若有 N 个 LoRA
   prevNode = fromKey
   for i in 1..N:
     loraNode = createLoraNode(
       id = allocateId(),
       loraName = request.loras[i-1].file,
       weight = request.loras[i-1].weight,
       pos = [loraInsertion.nodePos[0] + i * 50, loraInsertion.nodePos[1] + i * 50]
     )
     connect prevNode → loraNode.model
     prevNode = loraNode
   connect prevNode → toKey.input[targetSlot]

4. 更新 outputs[].links 与 inputs[].link
   确保双向一致性
```
